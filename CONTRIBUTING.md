# Как участвовать в разработке Ankh

Спасибо, что хотите помочь. Здесь — как собрать проект, где что лежит и каким должен быть pull request.

## Сообщить о проблеме

Откройте [issue](https://github.com/isaevfeed/ankh-ide/issues) и укажите:

- версию Ankh (тег релиза или коммит), версию macOS и процессор (Apple Silicon / Intel);
- агента и его версию (`claude --version`);
- шаги, чтобы повторить проблему, и что вы ожидали увидеть;
- строки из `~/Library/Application Support/Ankh/ankh.log`, если они относятся к делу.

Перед отправкой уберите из логов и скриншотов пути, имена репозиториев и код, которые нельзя показывать.

Для крупных изменений — новая панель, новая интеграция, смена поведения по умолчанию — сначала откройте issue с предложением, чтобы обсудить подход до того, как писать код.

## Окружение

- macOS 11+;
- Go 1.25+;
- Node 20+ (CI использует 22);
- Xcode Command Line Tools: `xcode-select --install`.

```bash
git clone https://github.com/isaevfeed/ankh-ide.git
cd ankh-ide
make setup        # go mod download + npm ci
make run          # собрать Ankh.app и открыть
```

Другие цели:

| Команда | Что делает |
|---|---|
| `make frontend` | собрать интерфейс в `frontend/dist` (встраивается в бинарник) |
| `make app` | собрать `build/bin/Ankh.app` под текущую архитектуру |
| `make universal` | то же для Apple Silicon и Intel |
| `make install` | собрать и положить в `/Applications` |
| `make test` | `go vet`, Go-тесты, проверка типов и тесты фронтенда |
| `make dev-web` | интерфейс в браузере, без Wails |

### Интерфейс в браузере

`make dev-web` поднимает тот же Go-сервис по HTTP на http://127.0.0.1:7777 — удобно для работы над интерфейсом и для Playwright. Вызовы и события идут через `/call` и `/events` вместо моста Wails. Настройки хранятся отдельно: `~/Library/Application Support/Ankh-dev`.

Проект добавляется запросом (выбор папки в браузере недоступен):

```bash
curl -s -X POST 127.0.0.1:7777/call -d '{"method":"AddProjectPath","args":["~/code/my-project"]}'
```

Чтобы не тратить лимиты, вместо настоящего агента можно подставить скрипт с именем `claude` раньше в `PATH`: он печатает что-нибудь и читает stdin.

## Устройство

Карта пакетов — в [README](README.md#как-это-устроено). Несколько правил, которые важно не сломать:

- **Бэкенд не знает о Wails.** `internal/app.Service` получает от `main.go` только функции из `Host` (события, буфер обмена, диалог, бейдж Dock). Поэтому тот же сервис работает в `cmd/devserver`.
- **Публичные методы `Service` вызываются из интерфейса.** Любой экспортируемый метод доступен фронтенду. Служебное оставляйте неэкспортируемым или делайте функциями пакета, как `app.Start` и `app.Shutdown`.
- **Мы вызываем инструменты пользователя**, а не встраиваем свои: `git`, `glab`, `tmux`, агента. Так работают его конфиги, хуки и авторизация. Новые зависимости Go и npm добавляйте, только если без них никак, и обсуждайте в issue.
- **Пути от интерфейса проверяются** через `fstree.Resolve`: чтение и запись вне папки сессии запрещены.
- **Платформенный код** лежит в файлах `*_darwin.go` / `*_darwin.c`, а рядом — заглушка `*_other.go`, чтобы пакеты собирались и тестировались на Linux.
- **Состояние интерфейса** хранится в `frontend/src/lib/store.ts` (свой стор на `useSyncExternalStore`). Селекторы должны возвращать стабильные значения: для пустых списков используйте `EMPTY`, иначе React уйдёт в бесконечный цикл перерисовки.

## Код

- Go: `gofmt`, `go vet` без замечаний. Ошибки, которые видит пользователь, пишем по-русски, коротко и с подсказкой, что делать.
- TypeScript: `strict`, без `any`. Компоненты — функции, без классов.
- Тексты интерфейса — на русском, на «вы», без восклицательных знаков. Кнопки называют действие: «Создать MR», а не «ОК».
- Стили — в `frontend/src/styles.css`, цвета только через переменные из `:root`. Проверяйте светлую и тёмную темы.
- Комментарии в коде объясняют «почему», а не пересказывают «что».

## Тесты

```bash
make test
```

- Логика без UI — с тестами: разбор диффа, git-операции (на временном репозитории), поиск, перенос замечаний, протокол ACP, нечёткий поиск.
- Тесты, которым нужны внешние программы (`git`, `tmux`, `python3`), пропускаются, если программы нет.
- Тесты фронтенда (`frontend/src/lib/*.test.ts`) запускаются встроенным `node --test`.
- Изменения в интерфейсе проверьте вручную в собранном приложении в обеих темах и приложите скриншот к PR.

## Pull request

1. Сделайте форк и ветку от `main`: `fix/stage-renamed-files`, `feature/search-history`.
2. Один PR — одно изменение. Рефакторинг и новое поведение — отдельными PR.
3. `make test` проходит, CI зелёный.
4. В описании: что меняется, зачем, как проверить; для интерфейса — скриншоты.
5. Сообщения коммитов — по-английски, в повелительном наклонении: `Stage removals with git rm --cached`.

Не включайте в PR код, логи и примеры из закрытых проектов — только свои или открытые.

## Релизы

Релиз собирает GitHub Actions: тег `vX.Y.Z` на `main` запускает [`release.yml`](.github/workflows/release.yml). Он собирает универсальный `Ankh.app`, публикует `Ankh-macos-universal.zip` и контрольную сумму в Releases. После этого [`install.sh`](install.sh) ставит новую версию.

```bash
git tag v0.2.0
git push origin v0.2.0
```
